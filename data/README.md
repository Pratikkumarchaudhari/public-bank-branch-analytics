# Static branch dataset — provenance and dictionary

**[View the CSV](branches.csv)** · [Download the raw CSV](https://raw.githubusercontent.com/Pratikkumarchaudhari/public-bank-branch-analytics/main/data/branches.csv) · [Analysis methodology](../docs/ANALYSIS_METHOD.md)

## Where did this data come from?

This is **synthetic demonstration data**, generated by `sample()` in [analysis.py](../analysis.py). It was not downloaded from FDIC, a bank, NYSDFS, or a commercial provider. It contains no real institution records. The CSV was already committed to this repository and is the published sample's input dataset.

| Property | Value |
|---|---|
| Grain | One branch ID in one observation year |
| Rows | 341 |
| Columns | 5 |
| Observation years | 2024: 170 rows; 2025: 171 rows |
| Distinct branch IDs across both years | 179 |
| Matched branch IDs between years | 162 |
| Fictional banks | 12 |
| States | CT, MA, NJ, NY, PA |
| Deposit unit | Thousands of US dollars, illustrative values |

## Column dictionary

| Column | Meaning | Example |
|---|---|---|
| `year` | Observation year | 2024 |
| `branch_id` | Synthetic branch identifier; repeat across years is expected | SYN0001 |
| `bank_id` | Fictional owning-bank identifier | BANK02 |
| `state` | State grouping label | NJ |
| `deposits_thousands` | Synthetic deposits in $000 | 42919.0 means an illustrative $42,919,000 |

The unique record key is **(year, branch_id)**, not branch_id alone. There are no addresses, latitude/longitude fields, or real bank names in this dataset.

## How generation works

The generator loops over years 2024 and 2025 and candidate integer IDs 1–180:

- In 2024, IDs above 170 are omitted.
- In 2025, IDs divisible by 19 are omitted.
- Branch IDs use `SYN` plus a zero-padded integer.
- Bank labels cycle using `(i % 12) + 1`.
- State labels cycle through NY, NJ, CT, PA, and MA.
- Deposits use a deterministic arithmetic formula:

```python
round(
    (35000 + (i * 7919) % 200000)
    * (1 + (year - 2024) * (0.025 + (i % 9) / 100)),
    2
)
```

Actual generation does not draw random values. Although the code initializes a NumPy random generator, that generator is not used to create these records.

The construction deliberately creates entering and exiting branch IDs for a reproducible cohort example. Such changes in a real export would need investigation before calling them actual openings or closures.

## Reproduce it

From the project root, after installing requirements:

```bash
python analysis.py
```

This recreates `data/branches.csv`, `outputs/summary.json`, and `outputs/state_metrics.csv`. The static HTML report is a saved snapshot and is not automatically regenerated by this command.

To explicitly analyze the saved CSV:

```bash
python analysis.py --input data/branches.csv
```

In that mode the output labels the input as user-supplied; this does not change the CSV's synthetic origin.

## Optional real data
